# PCDoc v0.1 — Socle + Système (lecture seule) + Bilan minimal — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** livrer une première version portable de PCDoc qui s'ouvre en administrateur dans une seule fenêtre Fluent FR/EN, affiche toutes les informations système (matériel, Windows, temps de démarrage, programmes au démarrage, tâches, services avec signature) et propose un Bilan « Analyser mon PC » avec note globale et problèmes classés 🔴🟠🟢.

**Architecture :** solution .NET 10 en couches (spec §3.1). Les projets *sans* dépendance Windows (`Core`, `Modules.System`, `Presentation`) ciblent `net10.0` et se testent partout, y compris sous Linux ; les projets Windows (`Infrastructure`, `App`) ciblent `net10.0-windows` et sont compilés/testés sur le runner Windows de GitHub Actions. Les modules lisent Windows uniquement via des interfaces déclarées dans `Core/Abstractions`.

**Tech Stack :** C# 14 / .NET 10 (SDK 10.0.100+), WPF avec `ThemeMode` (Fluent), CommunityToolkit.Mvvm (MIT), Microsoft.Extensions.Hosting (MIT), Serilog + Serilog.Sinks.File (Apache-2.0), System.Management (MIT), TaskScheduler / `Microsoft.Win32.TaskScheduler` (MIT), xUnit + FluentAssertions 7.x (Apache-2.0 — **pas la 8.x, licence commerciale**), GitHub Actions `windows-latest`.

**Spec :** `docs/specs/2026-11-03-pcdoc-vision-architecture-design.md` (validée).

## Global Constraints

- Nom de code « PCDoc » défini **une seule fois** : `<Product>` dans `Directory.Build.props` ; tout le reste le lit via `AppInfo.ProductName`.
- Licence GPL-3.0 ; toute dépendance doit être compatible (MIT, Apache-2.0, BSD, MPL-2.0…) et listée dans « À propos → Composants » avec licence et version.
- Windows 10 et 11 uniquement, x64.
- **Une seule fenêtre** : aucune console, aucun Explorateur, aucun navigateur, aucun outil externe visible. Tout processus lancé l'est avec `CreateNoWindow = true`, `UseShellExecute = false`. Seule exception : l'UAC au lancement.
- Manifeste `requireAdministrator`. Aucune technique de contournement de l'UAC.
- Analyse **toujours en lecture seule** : en v0.1 aucune écriture système (registre, services, tâches, fichiers hors `%LOCALAPPDATA%\PCDoc`).
- Aucune télémétrie, aucun appel réseau en v0.1.
- Interface FR + EN, choix dans l'app, changement à chaud. Aucun texte affiché codé en dur : tout passe par les ressources.
- Journal texte dans `%LOCALAPPDATA%\PCDoc\logs`, un fichier par jour, 14 jours conservés.
- `Nullable` activé, `TreatWarningsAsErrors` activé.

La v0.1 ne contient **aucune correction** (M2 en lecture seule). Les briques du Socle qui ne servent qu'aux corrections sont reportées au premier plan qui en a besoin, pour ne pas livrer du code jamais exécuté :

| Activer/désactiver démarrage/tâches/services (M2) | v0.2, avec le pipeline de sécurité | écriture système |

## Review Focus

1. **Classe WMI absente ou refusée** (pas de batterie sur un fixe, `WmiMonitorID` vide en VM/RDP, `MSFT_PhysicalDisk` indisponible) → la section affiche « Non disponible », la page et le Bilan ne plantent pas. Test : Task 8 `Collect_WhenWmiThrows_ReturnsUnavailableSections`.
2. **Journal Diagnostics-Performance vide ou désactivé** (VM neuve, journal effacé) → « Aucune donnée de démarrage », aucun finding de lenteur. Test : Task 9 `Read_WhenNoEvents_ReturnsEmptyHistory` + Task 11 `BootRule_WhenNoHistory_ProducesNothing`.
3. **Lignes de commande de démarrage atypiques** (`"C:\a b\x.exe" -min`, `C:\a b\x.exe /s` sans guillemets, `%ProgramFiles%\…`, `rundll32.exe x.dll,Entry`, fichier supprimé) → le bon fichier est vérifié ; un fichier introuvable est signalé « introuvable », jamais « non signé ». Tests : Task 10 `CommandLineParser` (cas listés).
4. **Binaires Windows signés par catalogue** (`notepad.exe`, beaucoup de services) → reconnus signés « Microsoft Windows » ; sinon le Bilan noierait l'utilisateur de faux positifs. Test : Task 6 intégration `Verify_CatalogSignedSystemFile_IsSigned`.
5. **Un module qui plante ou ne répond plus** → le Bilan se termine quand même, affiche « Analyse incomplète : Système » et les findings des autres modules. Test : Task 3 `Run_WhenScannerThrows_ReportsModuleError` et `Run_WhenScannerHangs_TimesOut`.

### Task 6 : vérification de signature numérique (Authenticode + catalogue)

**Files :**
- Create : `src/PCDoc.Core/Abstractions/ISignatureVerifier.cs`, `src/PCDoc.Infrastructure/Signatures/{SignatureVerifier,NativeMethods}.cs`
- Test : `tests/PCDoc.Infrastructure.IntegrationTests/SignatureVerifierTests.cs`

**Interfaces (Produces) :**
```csharp
public enum SignatureStatus { Signed, Unsigned, Invalid, FileNotFound, Error }
public sealed record SignatureInfo(SignatureStatus Status, string? Publisher, bool IsCatalogSigned);
public interface ISignatureVerifier { SignatureInfo Verify(string filePath); }
```

Algorithme (code maison, P/Invoke `wintrust.dll`, aucune dépendance) :
1. Fichier absent → `FileNotFound`.
2. `WinVerifyTrust` avec `WINTRUST_FILE_INFO`, action `WINTRUST_ACTION_GENERIC_VERIFY_V2`, `WTD_REVOKE_NONE`, `WTD_CACHE_ONLY_URL_RETRIEVAL` (aucun accès réseau), `WTD_UI_NONE`. Résultat 0 → signé ; `TRUST_E_NOSIGNATURE` → étape 3 ; autre code → `Invalid`.
3. Catalogue : `CryptCATAdminAcquireContext2` (SHA256, puis repli SHA1), `CryptCATAdminCalcHashFromFileHandle2`, `CryptCATAdminEnumCatalogFromHash`, `CryptCATCatalogInfoFromContext`, puis `WinVerifyTrust` avec `WINTRUST_CATALOG_INFO` (membre = hash en hexadécimal majuscule). 0 → `Signed`, `IsCatalogSigned = true` ; aucun catalogue → `Unsigned`.
4. Éditeur : `WTHelperProvDataFromStateData` → `WTHelperGetProvSignerFromChain` → certificat du signataire → `X509Certificate2.GetNameInfo(SimpleName)`. Toujours appeler `WTD_STATEACTION_CLOSE` et libérer les contextes catalogue (`finally`).
5. Résultats mis en cache par `(chemin, date de modification)` pour la durée d'une analyse.

- [ ] **Step 1 : tests intégration** `Verify_EmbeddedSigned_IsSigned` (`%windir%\explorer.exe` → `Signed`, éditeur contient « Microsoft ») ; `Verify_CatalogSignedSystemFile_IsSigned` (fichier de `System32` sans signature intégrée, identifié à l'étape 2 → `Signed`, `IsCatalogSigned == true`, éditeur contient « Microsoft ») ; `Verify_UnsignedTempFile_IsUnsigned` (petit `.exe` copié d'un octet modifié → `Invalid` ou `Unsigned`) ; `Verify_Missing_IsFileNotFound`.
